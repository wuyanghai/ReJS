# ReJS 1.0.0

Chrome / Edge Manifest V3 扩展：项目 → 多条规则，通过调试接口在原 URL 下替换 JS 响应并返回 **200 OK**。无本地辅助程序。浏览器会显示调试提示条，关闭提示或断开连接会停止替换。

## 功能一览

- 项目分组与多条规则，支持精确 URL、自动识别和正则表达式。
- 导入或编辑本地 JS 内容，按标签页启用，保留原 URL 并返回 200。
- 精简日志、错误筛选、重复合并与清空。
- Chrome / Edge 125+，无需 Node.js 即可使用扩展；Node.js 仅用于开发和测试。

## 安装与升级

1. 打开 `chrome://extensions` 或 `edge://extensions`，开启开发者模式。
2. 加载本项目的 `extension` 目录。升级时覆盖原目录并点击“重新加载”，不要卸载或改用新目录，以保留扩展 ID 和已有数据；如果新增调试权限需要确认，请在扩展管理页重新启用。
3. 打开插件的“管理项目”，先新建项目，再新建规则。原有项目与规则保留。
4. 选择“自动”“完整 URL”或“正则”，输入地址，导入 UTF-8 JS 文件或直接编辑内容，保存。
5. 回到目标网页，在插件弹窗选择项目，点击“启用当前页”，再点击“强制刷新”。

升级会清除本扩展 0.3.x 的旧重定向规则，避免残留 307；旧启用状态不自动继承，需要重新选择项目启用。保留 declarativeNetRequest 权限仅用于清理历史规则，不再创建重定向规则。不要同时启用另一个旧版插件副本。

## 匹配与项目

- 新规则默认自动模式：以 http:// 或 https:// 开头的输入按完整 URL 精确匹配（含查询参数），其他输入按 JavaScript 正则。
- 完整 URL 自动转义 `?`、`+`、`.` 等字符，去除首尾空白及不参与网络请求的 fragment。参数变化需修改规则或使用正则。
- 旧规则保持原匹配方式；以前误把完整 URL 当正则输入的规则，请编辑后切换到“完整 URL”。
- 正则支持空 flags 或 i，不允许 g/y；请避免灾难性回溯表达式。
- 项目内第一条启用且匹配的规则生效；支持排序、开关、编辑和删除。
- 每个标签页只启用一个项目，不同标签页可以使用不同项目。正在使用的项目需要停止替换后才能删除。
- 默认只替换 Script，可选择 Script + Fetch/XHR。仅处理 GET/HEAD。

## 替换行为

- 拦截响应阶段，在原服务器返回响应头后提供本地正文和 200 状态，URL 不变；原请求仍会发送到服务器。
- 保留原响应的 CORS、Cookie 和安全策略等头，移除旧内容的压缩、长度、缓存校验、范围及重定向信息，重新设置 JS MIME 和 no-store。
- 原请求的网络失败会记录错误并尝试放行，不承诺离线或上游不可达时可替换。
- 调试会话期间禁用网络缓存并绕过 Service Worker。支持主页面与自动附加的 iframe，独立 Worker 不保证覆盖。
- 内容保存为快照，不自动同步磁盘；原文件改动后需重新导入。每条最多 2 MB，空内容有效。
- 不修改页面 CSP 或移除 SRI。若页面声明的 integrity 与替换内容不符，浏览器仍可能拒绝执行。
- 浏览器重启、扩展重载、用户关闭调试提示或其他原因导致连接断开后，需要重新启用。打开 DevTools 后请检查插件连接状态。

## 日志

- “200 · 规则名”表示浏览器已接受替换响应，不代表业务逻辑正确。
- 不输出普通加载完成事件。重复记录在 2 秒内合并计数，每标签页最多 100 条、全局最多 500 条。支持仅错误筛选和清空。
- 记录相关 URL 的加载失败、网络错误及可关联到规则的脚本异常；不记录无关脚本的加载提示。
- 若脚本运行错误无法关联 URL，请查看页面 Console。

## 本地验证

在项目目录运行：

```powershell
python -m http.server 8765 --bind 127.0.0.1 --directory demo
```

打开 http://127.0.0.1:8765 ，新建项目及规则，使用以下正则并导入 `demo/replacement.js`：

```regex
^http://127\.0\.0\.1:8765/demo\.js(?:\?.*)?$
```

启用并刷新后应显示绿色“替换成功”，Network 中原 demo.js URL 返回 200。停止后刷新恢复原始脚本。

```powershell
npm install

npm run test:browser
```

测试在隔离浏览器配置运行，不使用日常浏览器数据。可用 `BROWSER_EXE` 指定 Chromium 可执行文件。

1.0.0 已在 Chrome for Testing 156.0.8078.4 验证原 URL 200、无重定向、普通/跨域模块脚本、Fetch、项目隔离、完整 URL 参数匹配、无关日志过滤、SRI 失败诊断和停用恢复。9 项单元测试覆盖旧重定向规则清理、失败放行、响应头处理、断开状态、日志合并/容量/清空与数据迁移。

## 正式发行包

`releases/rejs-1.0.0.zip` 解压后直接选择包含 manifest.json 的目录加载。SHA-256 见同目录校验文件。此发行包用于手动安装，未上传扩展商店。发布记录见 CHANGELOG.md。

重新打包：`npm run release`（Windows）。仅包含扩展文件、README、CHANGELOG 和 LICENSE，不包含 node_modules、研究源码和测试数据。
